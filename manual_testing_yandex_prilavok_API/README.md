# Проект: Тестирование API Яндекс.Прилавок

**Сервис:** приложение для заказа продуктов (бэкенд API + БД).  
**Цель:** проверить корректность работы API, соответствие ответов контракту и целостность данных в БД.

## Что было протестировано

### HTTP‑методы и сценарии
- **GET, POST, PUT, DELETE** — полная проверка CRUD‑операций.
- **Валидные и невалидные сценарии:** корректные запросы, неверные типы данных, пустые тела запросов.
- **Граничные значения:** проверка лимитов, минимальных/максимальных значений, граничных форматов.
- **Коды ответов:** соответствие ожидаемым HTTP‑кодам 

### Валидация данных
- **Структура JSON:** соответствие ответам спецификации (наличие обязательных полей, типы данных, вложенность).
- **Согласованность с БД:** через SQL‑запросы проверена целостность данных — соответствие записей в БД и ответов API.

## Подход к тестированию

- **Изучение документации API:** на основе Swagger сформированы чек‑листы и определены обязательные поля и форматы.
- **Декомпозиция сценариев:** для каждого метода выделены позитивные/негативные проверки и граничные значения.

## Артефакты проекта

В репозитории представлены:
- Чек‑листы (checklists/) — по каждому методу и типу проверок.
- Баг‑репорты (bug-reports/) — с примерами запросов (cURL), ответов API и SQL‑запросов, подтверждающих несоответствие.

## Инструменты и стек

- Тестирование API: Postman, Swagger
- Работа с данными: SQL‑запросы
- Документация: Google Sheets 

## Связь с автоматизацией и польза проекта

Проект демонстрирует навыки тестирования бэкенда и валидации данных — это хорошая основа для дальнейшей автоматизации API‑тестов. Чек‑листы спроектированы атомарно, с чёткими ожидаемыми результатами, что позволяет конвертировать их в автотесты (например, на pytest + requests). Особенно ценным был опыт кросс‑проверки API и БД: такой подход помогает выявлять скрытые дефекты, которые не видны только по ответам сервера.
