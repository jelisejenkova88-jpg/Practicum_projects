# Проект: Тестирование UI веб‑версии Яндекс Самокат (сквозные сценарии)

**Сервис:** веб‑версия Яндекс Самокат — бронирование и отслеживание аренды самокатов.  
**Контекст:** цель проекта — функциональное и исследовательское тестирование UI веб‑интерфейса (экран бронирования, статусы заказа).

## Особенность тестовой среды и подход к данным

На учебном стенде отсутствовала возможность создавать заказы напрямую из веб‑UI тестировщика. Для покрытия end‑to‑end сценариев я организовала сквозную проверку через смежные компоненты:
- **Создание заказа** выполнялось через API (Postman) — это позволило точно контролировать входные данные и граничные значения.
- **Действия курьера** (подтверждение, старт поездки, завершение) эмулировались через мобильное приложение (Android Studio, эмуляторы).
- **UI веба** проверялся как финальный слой отображения: корректность статусов, таймеров, истории и адаптивности.

Такой подход дал возможность протестировать не только вёрстку, но и всю цепочку передачи данных: API → бэкенд → мобильное приложение курьера → веб‑UI клиента.

## Что было протестировано в UI веба

- **Экран бронирования:** валидация полей, выбор самоката, обработка ошибок при отсутствии доступных единиц.
- **Экран «Статус заказа»:** отображение статусов (ожидает, в пути, завершён), таймеров, координат, истории действий.
- **Адаптивность и UX:** поведение на разных разрешениях
- **Исследовательское тестирование:** быстрые повторные клики, возврат на шаг назад, проверка отображения при потере связи.

## Подход к тест‑дизайну

- **Классы эквивалентности и граничные значения:** для статусов заказа и временных интервалов.
- **Декомпозиция требований и серые зоны:** выявлены сценарии, где UI не отображал промежуточные статусы или задерживал обновление таймера.
- **Сверка с макетами в Figma:** визуальное соответствие, отступы, состояния кнопок и индикаторов.

## Инструменты и методы диагностики

- **API:** Postman, Swagger — создание заказов и валидация JSON.
- **Мобильная часть:** Android Studio (эмуляторы) — действия курьера.
- **Веб:** DevTools — проверка адаптивности, сетевых запросов, JS‑ошибок.
- **Трафик:** Charles — анализ соответствия данных UI и ответов бэкенда.
- **Макеты:** Figma.

## Артефакты проекта

В репозитории представлены:
- Чек‑листы — быстрый регресс по статусам и экранам.
- Тест‑кейсы — сквозные сценарии с шагами по API, мобильному приложению и вебу.
- Баг‑репорты — дефекты с шагами воспроизведения

## Связь с автоматизацией и польза проекта

Проект показывает умение работать со сложной тестовой средой и строить end‑to‑end проверки даже при ограниченных возможностях UI.
